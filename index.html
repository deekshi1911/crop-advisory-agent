01

Introduction & Motivation

Smallholder and mid-size farmers routinely make three high-stakes decisions with incomplete information: which crop to sow given the current soil and weather, which fertilizer to apply given the crop and soil nutrients, and how to react to disease symptoms appearing on a leaf. Extension officers who could answer these questions are scarce relative to the number of farms, and the underlying agronomic relationships (nutrient interactions, climate suitability, disease symptomatology) are exactly the kind of structured, learnable pattern that supervised machine learning is good at.

This project builds a single Crop Advisory Agent that wraps three independently trained models — a crop recommender, a fertilizer recommender, and a leaf-image disease classifier — behind one interface, so a user supplies soil readings (and, optionally, a leaf photo) and receives a consolidated advisory report.

02

Problem Statement & Real-World Relevance

Problem. Given tabular soil/climate readings and/or a photograph of a crop leaf, predict (a) the most suitable crop, (b) the most suitable fertilizer, and (c) the disease present on the leaf (if any), along with a treatment recommendation.

Relevance. Incorrect crop choice wastes an entire growing season; incorrect or unnecessary fertilizer application wastes money and degrades soil over time; late disease identification can mean the difference between a treatable outbreak and a lost harvest. Each of the three sub-problems is individually well studied in agricultural ML literature — this project's contribution is combining them into one advisory pipeline with a shared interface and a disease → treatment knowledge lookup.

03

Objectives & Scope

  • Preprocess and clean three tabular/image dataset families into model-ready form.
  • Perform exploratory data analysis to understand class balance, feature correlation, and image characteristics before modelling.
  • Train and compare Decision Tree vs Random Forest classifiers for crop and fertilizer recommendation (tabular, structured data).
  • Train a Convolutional Neural Network for leaf-disease image classification (10 classes across Sugarcane, Cotton and Apple).
  • Evaluate every model with accuracy, precision/recall/F1 (macro), confusion matrices, and cross-validation.
  • Combine all three trained models into a single CropAdvisoryAgent class and expose it through a small Flask web app.

Scope boundary. The project targets the specific 24 crops, 21 fertilizers and 10 disease classes present in the supplied datasets — it is a proof-of-concept advisory pipeline, not a production agronomy system, and predictions should be read as decision support rather than as a substitute for expert advice.

Methodology

4.1 Dataset description & source

DatasetSizeClassesUsed for
Crop Recommendation2,790 rows24 cropsCrop recommendation
Fertilizer Recommendation756 rows21 fertilizersFertilizer recommendation
Sugarcane Leaf Disease2,521 images5 (incl. Healthy)Disease detection
Cotton Leaf Disease1,709 images4 (incl. healthy)Disease detection
PlantVillage (Apple subset)367 images1 (Apple scab)Disease detection

All three image sources were merged into one data/plant_images/ tree with <Crop>_<Class> folder names (e.g. Cotton_bacterial_blight), giving 10 combined classes and 4,597 images total.

4.2 Data representation & preprocessing

  1. Tabular (crop / fertilizer): null/duplicate removal, IQR outlier reporting, label-encoding of categorical columns (Soil Type, Crop Type, target labels), StandardScaler feature scaling, stratified 80/20 train-test split.
  2. Images: manifest build (filepath, crop, class label) via directory walk, stratified 70/15/15 train/val/test split, resize + normalise to [0,1]. The CPU baseline additionally extracts HOG (Histogram of Oriented Gradients) descriptors per image.

4.3 Exploratory data analysis

Class-balance bar charts, correlation heatmaps, per-feature distribution histograms, boxplot outlier checks (tabular); class distribution, sample grids, and image size/brightness sampling (images). Full results in §5.

4.4 Algorithm selection

Crop & fertilizer recommendation — Decision Tree and Random Forest were chosen because the inputs are low-dimensional, mixed continuous/categorical tabular features with non-linear thresholds (e.g. "rice needs rainfall > X mm"), which tree-based models capture naturally and interpretably, and Random Forest's bagging typically reduces the variance/overfitting a single Decision Tree is prone to on small tabular datasets.

Disease detection — a Convolutional Neural Network is the standard architecture for image classification because its convolutional filters learn local, translation-invariant texture/shape patterns (lesion shape, discoloration, leaf-vein disruption) directly from pixels, unlike tree models which need hand-engineered features.

4.5 Model training & validation

  • Crop / fertilizer: 5-fold cross-validation on the training split + held-out 20% test set.
  • Disease detection: train/val/test = 70/15/15; validation used for early stopping (CNN) / model selection (baseline).

4.6 Evaluation metrics

Accuracy, macro-averaged Precision / Recall / F1-score, per-class classification report, and confusion matrices for every model. Macro-averaging was used (rather than weighted) so that minority classes are not masked by majority-class performance — relevant here since the fertilizer dataset has 21 classes with few samples each.

4.7 Comparison of alternative approaches

Decision Tree vs Random Forest is compared directly for both tabular tasks (§6). For the image task, an MLP-on-HOG-features baseline is compared against a Random-Forest-on-HOG-features baseline as a CPU-only stand-in, alongside a full CNN specification intended for GPU training (§6.3).

4.8 Software implementation

All models are wrapped by agent/crop_advisory_agent.py's CropAdvisoryAgent class, and demonstrated through a Flask web form + JSON API in app/app.py (§8).

05

Exploratory Data Analysis & Visualization

5.1 Crop recommendation dataset

All 24 crop classes are perfectly balanced (62 rows each). Rainfall has the widest spread and the most IQR outliers (296 of 2,790 rows), reflecting genuinely different rainfall needs across crops rather than data error.

5.2 Fertilizer recommendation dataset

21 fertilizer classes, also perfectly balanced (42 rows each) across 756 rows — but 42 samples per class is thin for a 6-numeric-feature + 2-categorical-feature decision boundary, which shows up directly in model performance (§6.2).

5.3 Leaf image dataset

4,597 images across 10 combined classes; Sugarcane classes are best represented (~500 each), Apple scab the smallest (367).

Random Forest's bagged ensemble reduces the overfitting a single 12-depth Decision Tree shows (train-CV gap of ~3pp vs Random Forest's ~1.3pp), and wins on every metric. It was saved as the production model.

6.2 Fertilizer Recommendation — Decision Tree vs Random Forest

Decision Tree best model

Test accuracy27.6%
Macro F10.223
5-fold CV accuracy27.8%

Random Forest

Test accuracy22.4%
Macro F10.120
5-fold CV accuracy18.2%
Honest result, not a bug. Both models perform far below the crop model. With 756 rows spread across 21 classes (42 each) and only 6 numeric + 2 categorical features, many fertilizer pairs are not linearly or even tree-separably distinguishable from the given features alone — several fertilizers (e.g. different NPK-blend variants) likely overlap heavily in feature space. Random Forest actually does worse than a single Decision Tree here, which is a signature of a dataset too small/ambiguous for ensemble variance-reduction to help — the single tree is already underfitting, not overfitting.

6.3 Plant Disease Detection — CNN (GPU) vs CPU baseline (HOG + MLP / Random Forest)

The final model for this task is a Convolutional Neural Network (see models/plant_model.py → build_cnn()): four Conv2D+BatchNorm+MaxPool blocks, global-average-pooling, and a dropout-regularised dense softmax head, trained with augmentation (ImageDataGenerator: rotation, shift, zoom, flip) for up to 25 epochs with early stopping. This development environment has no internet access and cannot install TensorFlow/GPU drivers, so the CNN could not be executed here — it should be run on Colab or any TensorFlow+GPU machine (~15–20 min for this dataset size).

To still demonstrate the full train/validate/test/accuracy pipeline end-to-end, a CPU-only baseline was trained instead: HOG (Histogram of Oriented Gradients) descriptors extracted per image, classified with an MLP and a Random Forest.

MLP (HOG features)

Test accuracy53.6%
Validation accuracy53.6%
Macro F10.528
Train time3.4s

Random Forest (HOG features) best baseline

Test accuracy65.7%
Validation accuracy58.9%

A hand-crafted-feature baseline in the 55–65% range is a reasonable floor for this problem; published CNN results on comparable single-crop leaf-disease datasets (e.g. PlantVillage) typically reach 90%+ because convolutional filters learn lesion textures the HOG descriptor only partially captures. The gap here is expected and is exactly the argument for running the real CNN on GPU.

Results & Discussion

TaskBest modelTest accuracyMacro F1
Crop recommendationRandom Forest88.9%0.887
Fertilizer recommendationDecision Tree27.6%0.223
Plant disease detection (CPU baseline)Random Forest (HOG)65.7%0.647

The three tasks land at very different performance levels, and the reasons are traceable to the data rather than the algorithms: the crop dataset is large, clean, and features correlate strongly with the target (rainfall, humidity dominate feature importance); the fertilizer dataset is small and thinly spread across many classes; the image task is limited here by the lack of a true CNN, not by the data itself, which is large enough (4,597 images) to support one.

Across both tabular tasks, Random Forest's advantage over Decision Tree tracks dataset size: it wins convincingly on the 2,790-row crop dataset and loses on the 756-row fertilizer dataset — consistent with ensembling needing enough data per class to have something to average over.

08

Software Implementation

The CropAdvisoryAgent class loads all three saved models and exposes .recommend_crop(), .recommend_fertilizer(), .detect_disease(image_path) and a combined .full_advisory() method. A minimal Flask app (app/app.py) wraps it in a web form and a JSON API (POST /api/recommend).

Example run

$ python agent/crop_advisory_agent.py

{
  "crop_recommendation": {
    "recommended_crop": "rice",
    "confidence": 0.965
  },
  "fertilizer_recommendation": {
    "recommended_fertilizer": "Zinc Sulphate"
  }
}

Example disease detection

>>> agent.detect_disease("data/plant_images/Cotton_bacterial_blight/bact0.jpg")

{
  "crop": "Cotton",
  "predicted_label": "Cotton_bacterial_blight",
  "advisory": {
    "disease_label": "Bacterial_blight",
    "cause_type": "Bacterial",
    "symptoms": "Angular water-soaked leaf spots",
    "recommendation": "Apply copper oxychloride + streptocycline; use certified
                        disease-free seed; avoid overhead irrigation."
  }
}

Run the demo locally with python app/app.py and open http://127.0.0.1:5000. Full run instructions are in README.md.

09

Conclusion & Future Enhancements

This project demonstrates a working three-model agricultural advisory pipeline: a strong Random-Forest crop recommender (88.9% accuracy), a fertilizer recommender that honestly exposes the limits of its small training set (27.6% accuracy — reported rather than hidden), and a plant-disease classifier whose full CNN specification is provided but requires GPU access this environment doesn't have, with a CPU baseline (65.7% accuracy) standing in to prove the pipeline end-to-end.

Future enhancements

  • Train and report the actual tf.keras CNN on Colab/GPU in place of the HOG baseline.
  • Collect more fertilizer-recommendation rows per class, or reduce the class count by grouping chemically similar fertilizers, to give the model enough signal.
  • Add transfer learning (e.g. MobileNetV2 / EfficientNet fine-tuning) for the disease classifier to reach the 90%+ range typical of published PlantVillage results.
  • Extend the disease-recommendation lookup table to cover diseases outside the current 10 image classes.
  • Package the Flask app behind a proper front-end and deploy for real farmer use-testing.
